# Irori 标识 · 设计文稿

> 定稿于 2026-09-15。迭代这个标之前请先读一遍 —— 尤其是最后两节。

---

## 一、图形的意思

抽象化的**囲炉裏（いろり）**：日式民居地板上那个方形的下沉火塘。

拆开看正好是「囲」这个字：

| 图形 | 是什么 | 双关 |
|---|---|---|
| 外面一圈黑 | 炉缘（炉縁），「囲」外面那个**口** | 一块实心台面 |
| 里面四道凹槽 | 井桁框，「囲」里面那个**井** | Markdown 的 `#` |
| 正中那格再沉一层 | 火塘本身，亮着的是炭 | 你正在写的地方 |
| 升起来的那道 | 烟 | 取编辑器的源码标记色，和你写的 `#` 同一档灰 |

「井桁纹」本身也是一个很老的家纹，这一层不必点破，但它让「井」不只是笔画。

**取舍的底线**：这个标只有一处高饱和色（炭火），只有一道动势（烟）。加任何第三个焦点
都会让它散掉 —— 中途试过把台面改成金黄色，整个标的重心立刻从「炉」挪到「一块金砖」，
炉灰的意思没了。

## 二·五、应用图标的盘面

标本身是透明底的，`appicon.gen.mjs` 只负责两件事：

- **盘面** —— macOS 图标网格：1024 画布、824 主体、四周各留 100。圆角用超椭圆（n = 5）
  而不是 `rx` 圆角，曲率因此是连续的，跟系统自带图标的轮廓对得上。纸色上浅下深一点点
  （`#FCF9F3 → #EFE6D8`），加一层柔和投影和一圈极淡的内描边。

  > **这是整张图唯一用到渐变和半透明的地方**，属于平台惯例 —— Big Sur 之后的图标都有
  > 盘面纵深。标本身仍然是七种纯色。要绝对平涂就把 `PLATE_FLAT` 打开。

- **定位** —— 标的包围盒等比放到 `MARK = 600`（盘面的 73%）居中摆进去，再往下挪 8：
  标的视觉重心（台面）比包围盒中心低，上半让烟占了。600 试出来最稳：630 时台面几乎顶到
  盘面的圆角，540 又太小。

  > 标的 `clipPath` 用的是 `userSpaceOnUse`，会跟着外层 `transform` 一起变换，所以直接套
  > 一层 `<g transform>` 就行，不用改标自己的坐标。

## 三、版面：整张图只有一个线宽

穿过中心切一刀，从外到内：

```
炉缘 12 │ 留白 18 │ 笔画 12 │ 火塘 24 │ 笔画 12 │ 留白 18 │ 炉缘 12  = 108 = 2R
 2u        3u        2u        4u        2u        3u        2u    = 18u   (u = 6)
```

**炉缘（口）、井桁笔画（井）、笔画越过交叉点的出头，三者同为 2u。** 这是「该等宽的
地方」。火塘 4u 是唯一放大的一格，因为它是主角。

出头必须**等于**笔画宽度。中途试过 0.6 倍，「井」立刻读不出是四笔，变成一圈带疙瘩的
方环 —— 出头太短，眼睛把它们归给了交叉点而不是笔画。这是整个版面里最容易错的一处。

留白被出头和端头余地分掉：

```
M = OUT + 端头余地          （M = F - BO，F = R - B，BO = A + G）
```

这条恒等式让 `OUT` 一动，余地自动配平。改任何一个尺寸都由它兜底，不用手工重算。

四向对称不靠对齐眼力：井桁开口的二十八个角只写出四分之一，其余绕原点转 90° 生成。

## 四、等角投影的约定

标准 30° 等角，`+x` 往右下、`+y` 往左下、`+z` 往上：

```
sx = CX + SCALE · (x − y) · cos30
sy = CY + SCALE · ((x + y) · sin30 − z)
```

两条直接有用的推论，后面反复要用：

- **屏幕横坐标只跟 `x − y` 有关**，跟 z 完全无关。竖直的棱在画面上就是一条竖线。
- **沉 d 就是往下平移 `SCALE · d`**，没有横向分量。

镜头在 `(+1, +1, +1)` 方向，所以**外法线与 `(1,1,1)` 点积为正的面才看得见**。竖直墙面
的法线没有 z 分量，判据退化成 `n · (1,1) > 0`。

侧壁画到哪儿起、到哪儿止是**算出来的**，不是硬编码成「+x 和 +y 两个面」。逐段判上面
那个不等式，磨圆之后法线连续转动，侧壁会自己绕过圆角、在转到背光的那一刻收成零宽。

### 三层深度，靠剪裁而不是排序

```
z = 0            台面顶面 / 炉内地面
z = −D1  (−5)    井桁凹槽底
z = −D1−D2 (−11) 火塘底（炭）
```

深的两层**只可能透过开口看见**，所以 `clipPath` 本身就是遮挡关系：开口内先整块铺槽底
（开口整体下沉 D1），再把朝镜头的内壁盖到上缘 —— 没被槽底盖住的那一圈正好就是内壁，
不用另算。火塘是槽底上又一个凹坑，同样的办法再来一次。

改圆角、改深度，遮挡自己跟着走，不需要重排图层。

## 五、圆角：必须发生在投影之前

一开始图省事，直接对**投影后**的多边形倒角。结果台面顶面和侧面各磨各的，左右两个角上
侧面支出一块黑 —— 顶面那个角投影后是 60°、外轮廓那个角是 150°，同一个半径磨出来的弧
根本对不上。

**正确做法**：在世界平面里把方角换成圆弧、采样成折线，再整条送进投影。这样顶面、侧面、
遮挡边界全部自动一致。

采样密度按半径走（弦高误差压在 0.1 个世界单位以内）。回退量 `t = r / tan(半角)` 跟夹角
有关 —— 等角投影下角有 60° 也有 120°，固定回退量会让两者一胖一瘦。

### 同心收缩

炉缘内外圈的圆角半径必须差一个边宽：**内 = 外 − B**（生成器里 `RF` 默认就是这么取的）。
用同一个半径的话，黑边在四个角上会比直边处窄一截，「四边等宽」就破了。

`RS = 16` → 内圈 4。`RS` 再大，标会开始像一块圆角方砖而不是火塘；`RG` 超过 3.4，井桁
笔画的端头开始发胖，四笔的结构会糊。

## 六、缝隙：台面的立体感全靠它

台面顶面和两个侧面**同一个黑**。原来用明暗差表达转折，但侧面之间的色接缝在圆角处很别
扭；改成同色 + 缝隙之后干净得多。

两道缝：

1. **横缝** —— 侧壁整体下沉 `GAP`，顶面与侧面之间让出一道
2. **竖缝** —— 侧壁在最近那条棱上切开，左右各退 `GAP/2`

两道在直边处等宽，都是 `GAP · cos30 · SCALE = 9.0px @512`。

### 竖缝要按 `x − y` 退，不能按弧长

竖缝的宽度只由两端的屏幕横坐标决定，而屏幕横坐标**只跟 `x − y` 有关**（见第四节）。
沿直边退 c，`x − y` 正好变 c；沿半径 rr 的圆弧退同样的 c，`x − y` 却变了 `√2 · c`。
直角版本来是对的，一磨圆竖缝就宽了 41%。

### 横缝的下沉量取常数

横缝的可视宽度 = 下沉量 × |棱的屏幕横向分量|，所以它会随棱的斜度变。三种做法都试过：

| 做法 | 结果 |
|---|---|
| **下沉量取常数** | 垂直距离处处相等，两个尖角处收口干净 ← **采用** |
| 按切线补偿，让垂直于缝的宽度恒定 | 绕到左右尖角时补偿量发散，只能夹住；垂直距离反而变得不均匀 |
| 再让补偿量在尖角收到零 | 侧壁上缘与顶面轮廓合拢，缝在尖上被**焊死** —— 最差 |

常数下沉的代价只是近角那一小段缝宽出 15%（棱在那里转成水平）。可以接受。

缝是**透明**的，底色换了缝跟着换。副作用：放深色底上缝会消失，台面糊成一整块。真要在
深色上用，得把缝填成某个亮色 —— 但那样标就自带底色了，跟「背景无色」的初衷相反。

## 七、端头：倒不了角，只能补相切圆弧

左右两个尖角上，端面竖直，上缘在那里的切线**也正好竖直**。这是等角投影的必然 —— 轮廓
的侧影点就定义在「切线转成竖直」的那一刻，两条边必然几乎平行地碰头，夹角接近零，成一
根针。

**这种角不能倒角**：半径 r 的倒角要沿边回退 `r / tan(半角)`，半角趋零时发散。

也**不能削平**（把针尖横着切掉再给两个新角加圆头）—— 那是把尖角擦掉，不是磨圆。

正确做法是补一段与端面、上缘**都相切**的圆弧：

- 圆心取在距端面 `r` 处（横坐标 `x0 + sgn·r`），沿上缘找到切点 Q
- 圆弧从端面上的切点 A 转到 Q
- 因为圆心横坐标恰好是 `x0 + sgn·r`，**A 就是圆的极点，横坐标仍然是 `x0`**
- 所以边界一点没往里收，收掉的只是针尖那一小撮面积

**半径要小。** 切点落在距端点约 `1.5 × r` 处：`r = 7` 就吃掉 10px 轮廓，尖角朝上的姿态
整个没了；定稿用 `1.5`，放大 30× 才看得出那一小段弧。

竖缝两端是实打实的直角，照常倒角（`FIL = 5`）。

## 八、配色：七种纯色

没有渐变，没有半透明，不画背景。三种直接取自 `src/style.css`。

| 色 | 值 | 职责 | 来源 |
|---|---|---|---|
| 台面 | `#221C18` | 顶面和两个侧面同色，转折靠缝隙 | 偏暖的近黑，纯黑放纸色底上会发灰 |
| 炉灰 | `#F7F3EC` | 炉内地面 | 编辑器 `--paper` |
| 槽底 | `#231A15` | 井桁凹槽底 | |
| 槽壁 | `#33271F` | 凹槽内壁 | |
| 塘壁 | `#7E3D14` | 火塘内壁，被炭从下面照着 | |
| 炭火 | `#F0A44B` | 全图唯一的高饱和色 | |
| 烟 | `#C3B7A4` | | 编辑器 `--tok`（源码标记色） |

### 两条不能动的

- **烟不能用 `--paper`**。标放到编辑器自己的底色上，出了炉缘的那一截烟会整根消失 ——
  同色。`--tok` 比纸色深两档，在纸色底、白底、炉缘上都看得见。
- **凹槽内部的明暗差不能换成缝隙**。那不是接缝，是「这里凹下去了」唯一的线索；换成缝
  会漏出地面的纸色，看着像裂开而不是凹陷。台面的明暗差才是接缝，可以换。

### 渐变的教训

原来炭火有一圈高亮渐变，挂在默认的 `objectBoundingBox` 单位上。重构时换了一条 path
承载同一个渐变，它就跟着漂了。要用渐变就 `userSpaceOnUse` 钉死；定稿是干脆不用。

## 九、烟

一条中轴线加一条粗细曲线放样出来的带子。中轴线由三次贝塞尔串起来，每个拐点处切线竖直，
S 形因此是连续曲率的；粗细两端归零才收得出尖。

**左右换边刻意安排在 `y ≈ −65`**，也就是越过炉缘最远那个角（`y = −R = −54`）之后。
否则烟正好骑在那个角上，看着像被戳穿了。这一条是硬约束，改中轴线时要重新检查。

## 十一、迭代时最容易栽的地方

按踩到的顺序，四个 bug 全栽在同一件事上 —— **用眼睛验收几何**。

1. **法线方向随遍历顺序翻转。** 两条侧壁一条自由端在头、一条在尾。当时按切线在尖端取
   极限去猜正负，可那里切线正好竖直，x 分量的正负毫无意义。结果右侧那条渲成了领结。
   → 定向要一次性从几何定：看曲线往哪边走，看法线该朝哪边（内部总在上缘下方）。

2. **`while (out.length > 2)`。** 端面只有两个点，裁剪函数根本不进循环。四个直角的圆头
   一次都没生效，而「方角」看着像是设计选择，不像 bug，所以拖了好几轮。

3. **圆头半径数组下标写反。** 尖角那个接缝拿到了倒角半径，边被回退了 5px。注释里明明
   写着「不能往里收」，却没验证。

4. **`Array.reverse()` 是原地的。** 裁剪函数在 `want = 0` 时把原数组原样返回，紧接着
   `.reverse()` 就把调用方的数组翻了面。裁剪结果是对的，但调用方后面拿 `list[last]` 当
   贝塞尔控制点时取到了另一头，甩出一根横穿缝隙的刺。倒角关掉时翻两次正好抵消，所以只
   在倒角开着时露出来。

**5px 的内收在缩略图里根本看不出来，量一下就无所遁形。出问题先加一条测量，别先看图。**

```
小尺寸  32px 下仍读得出「黑框 + 中间一点火」
底色    纸色 / 白 / 深色 / 中灰 四种底上都看一遍（缝在深色底上会消失，已知）
动画    实际放进浏览器看一个整周期：烟根钉在炭火上不动、整条像一道波往上送；火和烟不同步
```

## 十三、两个变体：熄灭版与动画版

定稿于 2026-09-24。几何一律沿用圆润版，只有火塘里的事不同；两者都在 `hearth.gen.mjs` 的
`UNLIT` / `ANIMATED` 两个常量里定义，`export.mjs` 一起导出。

### 熄灭版（`irori-logo-unlit.svg`）

火**快**熄了，不是熄透了：`SMOKE: false` 把烟整条拿掉，炭火换成暗红 `#7A2F19`，塘壁只剩
一丝暖意 `#3E2419`（比槽壁 `#33271F` 略红）。六种颜色。

一开始做成 `FIRE: false`，火塘取凹槽的两个色变成一个纯黑的坑 —— 反馈是「不要彻底变黑，要
火星快要消散、带一点暗红的感觉」。暗红的深浅试过 `#6E2A17`，在 128px 下已经快认不出是红
了，往亮一档到 `#7A2F19` 才在小尺寸上仍读得出「余烬」。塘壁不跟着亮：光是从下面照上来的，
火都快灭了，壁上不该还有橙色。

它跟定稿的区别只在火塘那一个 `<g>` 内，`check.mjs` 逐字节比对火塘之前的所有标记。

### 动画版（`irori-logo-animated.svg`）

两个动作，全用 SMIL `<animate>` 声明，没有脚本没有样式表：放进 `<img>` 就会动（GitHub
README 也行），不支持 SMIL 的渲染器显示的就是定稿。

| 动作 | 做法 | 周期 |
|---|---|---|
| 炭火呼吸 | 火塘底和塘壁的 `fill` 在本色和同色相的暗色之间来回；一个周期里两次呼吸深浅不同，免得像节拍器 | 5.1 s |
| 烟飘舞 | 中轴线的**每个采样点**横向叠加一道从炉心向尖端传播的正弦波，整条烟像一道波被送出去；相位和振幅都按**弧长**走，振幅按 `u^ROOT` 从根部长起；尖端保留定稿的钩，随倾斜线性地从一边卷到另一边；粗细全程是定稿的；每一帧重新放样成带子，交给 `<animate attributeName="d">` | 3.5 s |

两个周期刻意错开，火和烟不会锁成一个拍子。

**为什么动中轴线，不是给整条路径套 transform。** 刚性的倾斜或平移会把烟根一起晃走，而
烟根必须钉在炭火里。位移加在采样点上而不是贝塞尔拐点上：拐点只有四个，太粗，只能表达
「尖端在晃」，表达不出一道波沿着烟往上走。带子的法线取自位移后的曲线，所以带子跟着波走。

**第一版的教训。** 第一版只位移四个拐点、振幅按 `s^2.2` 从根部长起、周期 7.2 s，为的是
保住第九节那条「烟不骑在炉缘最远角上」的净空。反馈是「太慢；只有上面在动，太难看；要整条
曲线像正弦函数发射出去的感觉」。于是振幅指数降到 0.6（整条都在动，只有根钉死）、波长数
1.5（能看到一整个波往上走）、周期减到 3.2 s。代价是摆到极限时烟会短暂盖过那个角尖 ——
烟画在最上层，是盖住角，不是被角戳穿；`check.mjs` 仍然逐帧量净空，只要求不深入超过 3px。

**第二版的教训：波要按弧长写，不能按贝塞尔参数写。** 第二版反馈「趋势对了，还是太慢；顶
部那一块曲线乱七八糟」。顶部乱的原因：中轴线三段贝塞尔里最后一段是尖端那个小钩，弧长只有
几个世界单位，却占了参数 t 的三分之一 —— 按 t 写的波有半个波长被塞进了那个钩里，钩自然
扭成一团。改成按归一化弧长 u 写相位和振幅之后，钩只分到一小截相位，整个跟着波走。速度
再减到 1.8 s / 2.2 s。

**第三版的教训：波要压过原来的 S，烟才会变向。** 第三版反馈「烟雾没有变向」。波的振幅
（5）比定稿 S 形自身的弯（±13）小，波只是在一条固定的 S 上起伏，烟永远先右后左。改法：
动画里把定稿 S 缩到 `BASE = 0.3`，波振幅加到 10，波主导，整条烟真的左右换向。波长数随之
降到 1.15 —— 1.5 时弯比带子还窄，内侧边会折出尖角。`u^ROOT` 在根部斜率无穷大，烟脚会
横着滑出炭火，所以前 `PIN = 12%` 的长度再乘一个 smoothstep 把脚钉住。

这一版起，第九节「烟不骑在炉缘最远角上」**只对静态定稿成立**：动画里烟每个循环都会从那个
角前面扫过去（烟画在最上层，是盖住角）。原来那三条「定稿是摆动中心 / 不超过振幅 / 角净空」
的验收随之换成「真的变向 / 烟根不动」。

**第四版的教训：尖端的钩要跟着烟一起转向。** 第四版反馈「差不多了，但尖尖在变向时不自然；
变向让体感速度快了 1.5～2 倍，可以慢一点」。钩原来跟着身子一起按 `BASE` 横向压扁，而且永远
朝右卷：烟往右倒时钩还朝右，压扁后钩又折成一个尖。改法：钩（第三段贝塞尔）不参与压扁，每
帧重建。`dir` 取钩下方那段烟的倾向（`tanh(−倾斜 / HOOK)`，平滑过零），钩的横向偏移乘 `dir`
镜像，高度按 `|dir|` 在「卷起的钩」和「同样长度的直尖」之间插值。烟直立经过中线的那一刻，
尖端就是一根直的，然后往另一边卷。直尖一开始只到钩的最高点，比钩短一截，粗细收得太急，成了
一个斜切的楔形；改成和钩的弧长一样长。烟周期放慢到 3 s。

**第五版的教训：烟不会甩。** 第五版反馈「像尾巴，不像烟：变向时会突然加速；宁可变向那一刻
变短、变圆，转过去以后再变长、变尖」。钩按 `dir` 直接镜像，`dir` 过零很快，尖端就被甩过去。
改法：

- 变向时钩整体朝钩根收缩，短到约等于自身半径（`CAP`），末端的粗细从「收成尖」换成半圆
  （`sqrt(1 − s²)`），就是一个圆头；新的倾向稳住后再按 smoothstep 长回去、收回尖。
- 波在钩上也跟着按同一比例缩：波是按定稿钩的长度铺的，钩缩成一截短头时不缩，会把短头横着
  剪成一个带缺口的团。
- `HOOK` 从 4 放宽到 13，转向占掉循环里更大一段时间。
- 关键帧从 20 加到 30，钩的收放不被线性插值切成折线。

`check.mjs` 加了一条：烟最高点在相邻关键帧间的最大位移不超过平均的 3 倍（改前 HOOK 9 时约
2.7×，峰值出现在转向那几帧）。

**第六版的教训：动画里不要钩。** 第五版的反馈只有一句「你自己看看丑不丑」。把一个循环等分
12 帧排成一排看：钩缩成的圆头像一排手指，半卷半圆时又冒出小尖嘴，钩也只在一边卷得完整 ——
确实丑。问题出在思路上：钩是静态图里「烟」的记号，一动起来就只能在「甩」和「变形」之间二选
一。改法是动画里干脆不要钩：

- 钩换成一段同样长度、竖直向上的直尖，尖端的形状完全交给波。整条烟每个点都在同一道行波上
  运动，没有任何一处会单独加速（最高点最大步长 / 平均步长从 2.6× 降到 1.6×，`check.mjs`
  的阈值随之收紧到 2×）。
- 粗细曲线改成 `WMAX · sin(π · t^TAPER)^1.1`，`TAPER = 0.45`（定稿是 0.75）：最粗处落到
  烟的下部，往上一路收细成一根细尖，像一缕真的在散的烟，而不是一只牛角。
- 转向那套机制（`HOOK`、`CAP`、圆头、钩上缩波）整个删掉。关键帧回到 24。

静态定稿仍然带钩，不支持 SMIL 的地方显示的就是它。

**第七版的教训：动画必须是定稿在动，不能是另一缕烟。** 第六版反馈「跟原来的图标完全不兼容，
长得完全不一样」。细尖、换了粗细曲线的那缕烟确实不丑，但它已经不是这个标的烟了。于是第六版
整个撤回，回到第四版（定稿的粗细、定稿的钩），只修「甩」这一个毛病：

- 甩的真正来源是 `dir = tanh(倾斜 / HOOK)`：tanh 在零点附近陡，钩几帧之内就从一边翻到另一边。
  改成**线性**：`dir = 倾斜 / 同侧最大倾斜`，钩翻转的快慢就跟驱动它的那道波一样。
- 分两侧各自归一化：缩小后的 S 让倾斜偏向一边，用同一个最大值时，另一边的钩只卷得到一半。
- 钩的高度按 `dir²` 插值（原来是 `|dir|`，在零点有折角），过零时平滑地经过一根等长的直尖。
- 粗细全程用定稿的曲线，`TAPER` 删掉。

`check.mjs` 的「烟不甩」改成跟踪烟的**末端顶点**（一个固定的物质点），不再取「最高点」：钩一
转，最高点会在钩顶和钩尖之间跳，假报一个尖峰。末端最大步长 / 平均步长 2.0×（tanh 版约
2.7×）；最大的几步出在钩卷起来的那一段，是末端沿弧线走得更远，连续的三四帧里平缓地升上去再
降下来，不是一两帧的突跳。

最后按反馈把炭火呼吸的频率减半（2.2 s → 4.4 s），再把两者整体放慢约 15%：烟 3.5 s、炭火 5.1 s。

**静态 `d` 属性就是定稿。** 动画各帧都不等于定稿，不支持 SMIL 的渲染器显示的仍是定稿。

**没有的东西**：没有透明度、没有渐变、烟的粗细不变。中途试过让粗细跟着波「一鼓一鼓」地往
上走（10%），2px 的效果肉眼几乎看不出，删了。

参数全在 `ANIM` 常量：

| 参数 | 定稿 | 说明 |
|---|---|---|
| `FRAMES` | 24 | 每个烟循环的关键帧数，帧间线性插值 |
| `SMOKE_DUR` `FIRE_DUR` | 3.5 / 5.1 s | 两个周期 |
| `AMP` | 10 | 波的振幅（世界单位；≈ 21px @512、5px @128）。要大于定稿 S 自身的弯，烟才会变向 |
| `WAVE` | 1.15 | 整条烟上的波长数。> 1.3 时弯比带子窄，内侧边折出尖角 |
| `ROOT` | 0.6 | 振幅从根部长起的指数。远小于 1，整条都在动 |
| `PIN` | 0.12 | 从根部起这一段长度内波用 smoothstep 渐入，把烟脚钉在炭火里 |
| `BASE` | 0.3 | 动画里保留多少定稿 S 形。1 = 只在固定 S 上起伏（不变向），0 = 纯正弦 |
| `EMBER_DIM` `EMBER_DIM2` | `#CF7F2E` `#E2953F` | 深呼吸 / 浅呼吸时的炭火 |
| `PWALL_DIM` `PWALL_DIM2` | `#6B3211` `#753815` | 塘壁跟着走，摆幅小一档 |

文件约 110KB，全是那 25 帧的路径。嫌大可以减 `FRAMES`。
